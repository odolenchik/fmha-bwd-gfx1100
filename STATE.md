# Состояние проекта fmha-bwd-gfx1100 (05.05.2026)

## Цель проекта
Создать высокопроизводительный backward-проход для Multi-Head Attention (MHA) на AMD Radeon RX 7900 XTX (RDNA3, gfx1100) с использованием WMMA-инструкций для ускорения обучения диффузионных моделей (FLUX.2 Klein, HV1.5, WAN2.2) с LoRA/DoRA.

## Структура папок и файлов
- **src/fmha_bwd_kernels.cpp** – основной файл с C-ядрами. Сейчас содержит полный backward на rocBLAS (медленный, но корректный).
- **test_dq_final.hip** – эталонное WMMA-ядро для операции `dQ = dS @ K`. Работает правильно (ошибка 0.0).
- **CMakeLists.txt** – конфигурация сборки (только rocBLAS-версия).
- **test_full_correctness.py** – сравнение нашего backward с PyTorch (без softmax).
- **test_softmax_correctness_fixed.py** – сравнение с PyTorch с учётом softmax.
- **test_final_benchmark.py** – замер скорости текущего rocBLAS-бэкенда.
- **.gitignore**, **pyproject.toml** – вспомогательные файлы.

## Что уже работает (проверено)
- **rocBLAS-бэкенд**: `fmha_bwd_grouped_rocblas` (в src/fmha_bwd_kernels.cpp) – даёт корректные градиенты (ошибка < 0.1), но **медленный** (~8 ms на 1x16x1024x1024x64, PyTorch ~1 ms). Причина: многократные копирования row↔col.

## Что сейчас в разработке (WMMA-бэкенд)
- **Изолированный `dQ`**: файл `test_dq_final.hip` – доказал, что мы умеем правильно умножать матрицы через WMMA с `bfloat16`. Последний тест показал `dQ = -32.0` (ожидаемое значение).
- **Остальные ядра (`dP`, `dK`, `dV`)** – требуют аналогичного исправления индексации и структуры (shared memory, фрагменты). После этого можно собирать единый fused-бэкенд.

## Что не работало (архив ошибок)
- **Первые попытки WMMA** – путали `row_major`/`col_major`, неверно передавали `lda`, не использовали shared memory.
- **Triton-эксперимент** – показал, что в текущей версии PyTorch компиляция Triton не даёт ускорения для нашей задачи (скорее всего, из-за отсутствия fused-ядер для RDNA3).
- **hipBLASLt** – пытались собрать и использовать, но получили нестабильное поведение и проблемы с memory out-of-memory (OOM).

## Куда двигаться дальше (план)
1. **Перенести исправленную логику из `test_dq_final.hip` в `src/fmha_bwd_kernels.cpp`** – создать ядра `dP`, `dQ`, `dK`, `dV` по тому же шаблону.
2. **Добавить softmax backward** (у нас есть проверенное ядро из старой кодовой базы).
3. **Объединить всё в одно fused-ядро** – обрабатывать все 16 голов в одном kernel launch (сетка по `blockIdx.z`).
4. **Сравнить скорость с PyTorch** – если обгоним хотя бы в 1.5–2 раза, проект можно считать успешным.
5. **Упаковать в Python-модуль** – для удобного использования в тренировочных скриптах.
6. **Опубликовать на GitHub** – с инструкцией для владельцев 7900 XTX.
