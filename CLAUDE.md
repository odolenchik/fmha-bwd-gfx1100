# CLAUDE.md - Instructions for the Claude Agent

  ## Project Overview
  This repository implements high‑performance FlashAttention backward kernels
  for AMD ROCm (GFX1100) using HIP and rocWMMA. The goal is to optimise the five
  kernels of the FMHA backward pass (dp, softmax_bwd, dq, dk, dv) to approach
  or exceed PyTorch’s performance while preserving numerical correctness.

  ## Directory Structure
  - `src/` – HIP source files containing the fused kernels.
  - `kernel/correct/` – Reference WMMA‑based kernel implementations (not yet
  integrated into the main build unless explicitly copied).
  - `tests/` – Unit and integration tests (PyTorch comparison).
  - `build/` – Build directory (generated by CMake).

  ## Build Instructions
  ```bash
  mkdir -p build && cd build
  cmake ..               # Defaults to Release with -O3 and -D and
  -DROCWMMA_ENABLE_BF16=ON
  make -j$(nproc)        # Builds libfmha_bwd_bf16.so and libfmha_bwd_fp16.so

  Running Tests

  Isolated Kernel Tests

  python3 tests/test_dp_isolated.py      # dp_kernel
  python3 tests/test_dq_isolated.py      # dq_kernel
  python3 tests/test_dk_isolated.py      # dk_kernel
  python3 tests/test_dv_isolated.py      # dv_kernel
  python3 tests/test_softmax_isolated.py
  python3 tests/test_integration.py     # Full backward pass

  Benchmark vs PyTorch

  python3 benchmark_pytorch_final.py
  Measures the full fused backward pass (all five kernels) and compares
  execution time and numerical error against a PyTorch reference.

  Development Workflow

  1. Select a kernel to optimise – follow the order in WORK_PLAN.md:
  dp → dq/dk/dv (WMMA) → softmax_bwd → HIP‑graph.
  2. Modify the kernel in src/fmha_bwd_kernels.hip (or copy a WMMA version from
  kernel/correct/ and add the head_idx offset).
  3. Ensure the kernel compiles (make -j$(nproc)).
  4. Verify correctness with the corresponding isolated test.
  5. Run the integration test to confirm no regression.
  6. Measure performance with the benchmark script.
  7. Iterate until the target speed‑up is reached.
  8. Commit changes with a clear message; if touching production files, bump the
  version in pyproject.toml.

  Coding Conventions

  - Follow the existing code style in src/fmha_bwd_kernels.hip.
  - Use __restrict__ for pointer arguments where appropriate.
  - Prefer bfloat16 (rocwmma::bfloat16_t) for storage; accumulate in float.
  - Add __syncthreads() after shared‑memory writes before reads.
  - Keep kernel launch configuration consistent with the tile sizes defined in
  kernel/correct/fmha_bwd_config.h (BM=64, BN=64, BK=32, BLOCK_SIZE=512,
  LDS_PAD=8).
  - Do not add #pragma suppression comments; fix the underlying issue.

  Versioning

  When committing changes that affect production files (src/**, kernel/**,
  CMakeLists.txt, etc.), update the version in pyproject.toml according to
  SemVer:
  - PATCH – bug fixes and refactors without behavioural change.
  - MINOR – backward‑compatible new features or performance improvements.
  - MAJOR – breaking changes.
  Run uv lock after updating the version and commit both files together.
